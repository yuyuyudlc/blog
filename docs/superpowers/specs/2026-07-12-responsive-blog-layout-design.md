# 响应式博客排版与中文界面设计

## 目标

在保留现有技术日志视觉体系的前提下，修复桌面端和移动端的排版问题，将界面统一为中文，并让中英文文章都获得稳定、易读的字体表现。

## 范围

本次包含：

- 桌面端与移动端 Header 响应式布局。
- 文章页滚动模型、元信息侧栏和标题尺寸。
- 浅色主题次要文字对比度。
- 中文界面文案、中文日期和阅读时长显示。
- 中英文混排字体栈及字体加载方式。
- 减少动态效果偏好。

本次不包含搜索、分页、文章目录、上一篇/下一篇或内容管理功能。

## 方案选择

采用适度结构调整方案：保留现有卡片、网格、装饰线条和主题风格，只调整 Header、文章元信息区域以及滚动容器的结构。相比单纯追加媒体查询，该方案能消除双重滚动的根因；相比完整重设计，它不会改变现有品牌气质。

## 响应式 Header

桌面端保持 57px 高的单行三列布局：左侧 Logo、中间分类导航、右侧主题切换。

在 767px 及以下视口中，Header 改为两行：

1. 第一行显示 Logo 和主题切换按钮。
2. 第二行显示分类 Tab，并允许横向触摸滚动。

移动端 Tab 不换行、不挤压 Logo，不显示原生滚动条；导航两侧使用轻微渐隐或边界暗示可继续横向滑动。Header 继续吸顶，触控目标保持至少 32px 高。

## 文章页滚动和布局

文章页在所有尺寸下恢复浏览器自然页面滚动，不再把视口高度固定到 Header 以下，也不在正文内创建独立滚动容器。

桌面端保留 280px 元信息侧栏和正文两列结构。侧栏外层负责贯穿文章区域的分隔线，侧栏内部内容在滚动时吸顶，避免破坏整列边界。

在 991px 及以下视口中，文章页改为单列。元信息区域不再限制为 220px，也不产生独立滚动条；信息以紧凑的两列网格呈现，标签跨整行。窄屏下自动退化为适合内容宽度的布局。

文章主标题使用响应式字号：移动端控制在约 34–36px，桌面端最高保持现有 52px，避免长英文标题在窄屏占据整屏。

正文继续保持约 17px 字号和 1.7 行高。代码块保留横向滚动，不扩大页面宽度。

## 中文界面与中英文文章

网站界面文案统一为中文，包括：

- 首页说明、卡片操作提示和空状态。
- 返回文章列表、文章元信息标签和文章结束标识。
- 主题切换的辅助文本、提示消息和按钮标题。
- 页脚链接与版权说明。

文章的标题、摘要、正文、分类和标签继续按作者原文显示，因此同一站点可同时发布中文和英文文章。

日期在展示层输出中文格式，例如 `2026年6月28日`。阅读时长输出为 `约 6 分钟`。文章源文件中的日期和时长数据应保持可稳定解析的结构；必要时将日期元数据规范为 ISO `YYYY-MM-DD`，但不改写文章内容。

## 字体策略

使用 Next.js 当前版本支持的字体加载方式，替代 CSS `@import`，减少首屏字体阻塞和排版跳动。

- 英文无衬线：IBM Plex Sans。
- 英文衬线标题：IBM Plex Serif。
- 等宽信息与代码：IBM Plex Mono。
- 中文无衬线回退：`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、系统无衬线。
- 中文衬线回退：`Songti SC`、`SimSun`、`Noto Serif CJK SC`、系统衬线。

移除 Cascadia Code 的最高优先级，确保等宽信息在不同平台上的视觉气质一致。中文字符使用系统已有的高质量 CJK 字体，英文和数字继续由 IBM Plex 系列渲染。

## 颜色、动画与可访问性

浅色主题的次要文字颜色需要达到普通小字号文本至少 4.5:1 的对比度。深色主题保持现有层级，只在必要时微调。

新增 `prefers-reduced-motion: reduce` 规则，关闭页面淡入、线条展开、旋转背景和非必要过渡。键盘焦点样式、语义化导航、文章主体和辅助文本继续保留。

## 测试与验收

自动化检查覆盖日期与阅读时长格式化，以及关键中文界面输出。项目必须通过 lint 和生产构建。

视觉验收至少覆盖：

- 1440×1000 桌面端首页和文章页。
- 390×844 移动端首页和文章页。
- 浅色与深色主题。
- 移动端分类 Tab 可横向滚动且不与 Logo、主题按钮重叠。
- 文章页只存在页面级纵向滚动，元信息和正文没有第二个纵向滚动容器。
- 长英文标题、中英文正文和代码块均不产生页面级横向溢出。

## 非目标与风险控制

不引入新的 UI 框架或状态管理依赖。结构调整限制在现有组件边界内，避免重写卡片和文章渲染逻辑。字体实现必须先核对项目内 `node_modules/next/dist/docs/` 的当前版本指南，不能依赖旧版 Next.js 用法。
